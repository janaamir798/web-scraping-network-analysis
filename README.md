# Analyzing Website Data Collection Efficiency and Network Behavior Using Multiple Web Scraping Techniques

**Team:** Jana Alamir, Rim Zoghbi
**Data:** English Premier League 2023-2024 (20 teams, 380 matches) from [TheSportsDB](https://www.thesportsdb.com)

We collect the same 380 matches with three methods (API, BeautifulSoup, Selenium), compare their performance
(time, requests, bandwidth, latency), observe their network behaviour with Linux tools and Wireshark,
test security measures (rate limiting, multithreading, ufw, Tor), and use the data for machine learning
(predicting the scores and results of the last 100 matches).

## Project structure

scraper_api.py # API scraper (TheSportsDB free V1 API); “python scraper_api.py tor” runs it through Tor
scraper_bs4.py # BeautifulSoup scraper (website HTML)
scraper_selenium.py # Selenium scraper (headless Chrome, metrics from Chrome’s network log)
scraper_api_threaded.py # multithreaded API scraper: “python scraper_api_threaded.py <threads>“
test_https.py, test_tor.py # small tests used for the ufw and Tor experiments
network_analysis.ipynb # performance comparison + network analysis with screenshots
ml_analysis.ipynb # EDA, features, regression, classification, predictions
data/ # scraped datasets, metrics.csv, predictions_last100.csv
figures/ # charts generated by the notebooks
screenshots/ # ss, nload, iftop, Wireshark, ufw and Tor screenshots
captures/ # tcpdump packet captures (.pcap), opened in Wireshark
requirements.txt # exact Python package versions


## Setup (WSL2 Ubuntu)
```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```
Selenium also needs Google Chrome installed (`google-chrome --version`). Selenium Manager downloads the matching ChromeDriver.

## How to run
```bash
python scraper_api.py              # -> data/matches_api.csv + one line in data/metrics.csv
python scraper_bs4.py              # -> data/matches_bs4.csv
python scraper_selenium.py         # -> data/matches_selenium.csv
python scraper_api_threaded.py 4   # -> data/matches_api_threaded_4.csv
python scraper_api.py tor          # requires the Tor service: sudo systemctl start tor
jupyter notebook                   # then open network_analysis.ipynb and ml_analysis.ipynb
```
Each scraper waits 5 s between requests and retries with exponential back-off on HTTP 429 or network errors.

## Key results (final runs, 21 Nov 2026)
| Method | Time (s) | Requests | Bandwidth (KB) | Avg latency (ms) | Bytes on the wire (KB) |
|---|---|---|---|---|---|
| API | 9.26 | 42 | 675 | 218 | 512 |
| BS4 | 22.99 | 38 | 1,907 | 574 | 711 |
| Selenium | 304.72 | 2,175 | 72,524 | 3,478 | 101,611 |

- **Recommended method: the API** with a polite delay. It is the fastest and lightest. Its free shared key was
  rate-limited (about 12 requests, then a 2-minute block), so respecting the limit is essential.
- **Selenium** made 57 requests per page, and about half of its traffic came from Chrome itself (background downloads).
- **Multithreading** did not help: the server's rate limit is the bottleneck (18 requests refused with 4 threads).
- **ML:** Logistic Regression predicted 58% of the last 100 results (baseline "always home win": 46%);
  Linear Regression predicted goals with a mean absolute error of about 1 goal.
